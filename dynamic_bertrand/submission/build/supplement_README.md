# Online Supplement: code and results

Supplementary material for the manuscript "Price Competition and Capacity Investment in LLM Inference Markets: A Dynamic Bertrand-Edgeworth Game". Everything needed to reproduce the numerical results is included; all inputs are generated by the code or taken from the public sources cited in the paper.

## Requirements
Python 3.10 or later with `numpy` and `matplotlib` (`pip install -r requirements.txt`). No GPU is needed. Run times below are for a laptop-class CPU with four cores. All random starting points are seeded.

## Files and where they appear in the paper

| File | Purpose | Paper |
| --- | --- | --- |
| `bertrand_mpe.py` | Model: capacity-constrained Bertrand game with capacity investment, logit Markov perfect equilibrium (reference solver `solve_mpe`, fast decoupled solver `solve_decoupled`), joint-profit benchmark, market-share contest. `python bertrand_mpe.py` (about 2 min) writes `results/dynamic_bertrand.json`, `results/price_by_state.png`, `results/benchmarks.png`. | Sections 3, 5; Table 3; Figure 1 |
| `equilibria_states.py` | Behavior at selected states in the two base-scenario equilibria (`results/equilibria_states.json`). | Table 2 |
| `sensitivity.py` | 20 scenarios x 4 starting points; checks of Propositions 2 and 3. About 1 hour on four cores. Writes `results/sens2/` and `results/sens2_summary.json`. | Section 6; Table 4 |
| `make_sens_tables.py` | Collapses the scenario files into `results/sens2_rows.json` and `results/sensitivity_capacity.png`. | Table 4; Figure 2 |
| `theory_checks.py` | Exhaustive enumeration of pure Markov profiles in the two-price alternating game. `python theory_checks.py verify` writes `results/theory_checks.json`. | Propositions 4 and 5; Appendix B |
| `price_game.py` | Alternating-move pricing at fixed capacities (Newton continuation in the noise scale). Writes `results/price_game.json`. | Section 7.3; Table 6 |
| `make_price_figs.py` | Price-path figure from `results/price_game.json`. | Figure 3 |
| `alternating.py` | Alternating-move game with capacity (value iteration, Newton continuation). | Section 7.4 |
| `joint_dynamic.py`, `joint_dynamic_starts.py`, `joint_dynamic_sens.py` | Joint price and capacity game against simultaneous pricing: main runs, multiple starts, 17 scenarios. Write `results/joint_dynamic*.json`. | Section 7.4; Table 7 |
| `timing_experiment.py` | Controlled timing experiment (designs C0, C1, C1s, C2). About 4 min on four cores. Writes `results/timing_experiment.json`. | Section 7.5; Table 8 |
| `empirical/build_price_panel.py` | Rebuilds the monthly price panel from the git history of the LiteLLM price file (needs `git clone --filter=blob:none --no-checkout https://github.com/BerriAI/litellm <dir>`). The resulting panel is included as `empirical/price_panel.csv.gz`. | Section 8.3 |
| `empirical/analyze_repricing.py` | Host-level regressions on the price panel. Writes `results/empirical_repricing.json` and `.png`. | Section 8.3 |
| `empirical/collect_openrouter.py`, `empirical/analyze_snapshots.py` | Collector for a prospective daily panel of provider-level prices and availability from a public API, and its analysis (runs after 28 days of data). `empirical/snapshots.csv` holds the single snapshot taken so far. | Section 8.3 |

## Suggested order
1. `python bertrand_mpe.py`
2. `python equilibria_states.py`
3. `python sensitivity.py --workers 4` then `python make_sens_tables.py`
4. `python theory_checks.py verify`
5. `python price_game.py` then `python make_price_figs.py`
6. `python joint_dynamic.py`, `python joint_dynamic_starts.py`, `python joint_dynamic_sens.py`
7. `python timing_experiment.py`
8. `python empirical/analyze_repricing.py`

## Notes
- The reference solver `solve_mpe` solves the full joint-action game and is several times slower than `solve_decoupled`; the two agree to five decimals in the base scenario (Appendix B of the paper).
- Plain value iteration for the alternating-move games converges only for large payoff noise; smaller noise is reached by Newton continuation, and some runs do not converge. The convergence flags are stored in every result file, and the paper reports which scenarios are affected.
- Parameters are illustrative, not estimated. The public data used in the paper are cited there; `empirical/price_panel.csv.gz` is derived from a community-maintained file of list prices and is not a record of transaction prices.

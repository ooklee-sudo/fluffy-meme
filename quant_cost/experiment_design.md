# 행동 실험 설계안: 로컬 LLM vs 클라우드 API 소싱 의사결정의 행동적 실물옵션

> 상태: 설계 초안. 수치(정확도, 비용)는 `quant_cost` 측정 결과로 교체해야 하고, 서지·도구(Prolific 요금, 척도 출처)는 투고 전에 직접 확인한다.

## 1. 목적과 논리

규범 모형(실물옵션)이 "언제 로컬 구축에 투자해야 하는가"를 예측하면, 관리자가 그 예측에서 **어디서 어떻게 벗어나는지**를 실험으로 검증한다. 규범 예측은 `quant_cost` 측정값(q_l(b), c_l, c_a, PII 노출)으로 보정한다.

## 2. 규범 벤치마크 (실험 조건을 가르는 기준)

로컬 구축의 절감 가치 V가 기하 브라운 운동(드리프트 μ=0, 변동성 σ)을 따르고, 구축비 F는 비가역이며 할인율 r이라 하자. 투자 임계는 V* = [β/(β−1)]·F 이고, β는 ½σ²β(β−1) + μβ − r = 0 의 양의 근이다.

r = 8%, μ = 0일 때 임계 비율 β/(β−1):

| σ | β | 임계 비율 |
| --- | --- | --- |
| 0.10 | 4.53 | 1.28 |
| 0.30 | 1.92 | 2.08 |
| 0.50 | 1.44 | 3.26 |

시나리오 설계: **V/F = 1.8**로 고정한다.
- 저변동(σ=0.10): 1.8 > 1.28 → **지금 구축이 최적**
- 고변동(σ=0.50): 1.8 < 3.26 → **기다리는 것이 최적**

즉 같은 V와 F에서 변동성만 바꿔도 규범 정답이 뒤집힌다. 이것이 H1 검정의 핵심이다. (같은 V/F에서 "지금 투자해도 되는 최대 F"는 저변동 0.78V, 고변동 0.31V.)

## 3. 가설

| | 내용 | 규범 예측 | 행동 예측 |
| --- | --- | --- | --- |
| **H1** 변동성 둔감 | 변동성(σ) 증가에 따른 대기 증가가 규범 예측보다 작다 | 고변동 셀에서 "지금 구축" 선택 0% | 고변동에서도 "지금 구축" 비율이 유의하게 높다 |
| **H2** 프라이버시 사고 가용성 | 사고 사례에 노출되면 로컬 선호와 추정 유출확률이 올라간다 | 기저율을 같게 제시했으므로 효과 없음 | 사고 사례 조건에서 로컬 선택↑, 추정 유출확률↑, 후자가 전자를 매개 |
| **H3** 성능 제시 프레이밍 | 정확도(%)만 제시하면 정답당 비용을 같이 제시할 때보다 로컬 선택이 줄어든다 | 두 제시는 정보가 동등하므로 효과 없음 | 정확도만 제시 시 API 선호↑ (정확도 격차에 고착) |
| **H4** 현상 유지/매몰비용 (Study 2) | 기존 API 계약에 이미 쓴 비용이 클수록 전환이 늦어진다 | 매몰비용은 무관 | 매몰비용 크기와 전환 지연이 양의 관계 |

## 4. Study 1: 2×2×2 피험자 간 설계 (H1–H3)

**요인 (모두 피험자 간, 무선 배정)**

| 요인 | 수준 |
| --- | --- |
| 변동성 | 저(σ=0.10 표현: "가격·성능이 향후 1년 거의 안정적") / 고(σ=0.50: "API 가격과 소형 모델 성능이 크게 변할 수 있음") |
| 프라이버시 사고 노출 | 없음 / 있음 (같은 업종 기업의 유출 사고 사례 1문단, **제시하는 유출 기저율 수치는 두 조건에서 동일**) |
| 성능 제시 | 정확도(%)만 / 정확도 + 정답당 비용 |

**시나리오**: 중견 기업의 CIO(또는 IT 의사결정자)가 고객 문서 처리에 쓸 LLM을 정한다. 현재 API를 쓰는 중이거나 신규 도입 단계다(Study 2에서 현상 유지 조작). 로컬 소형 모델 구축에는 일회성 비용 F가 든다. 제시하는 숫자(정확도, 요청당 비용, PII 노출 건수)는 `quant_cost` 측정값으로 채운다.

**종속변수**
1. **DV1 선택**: (a) 지금 로컬 구축, (b) 12개월 기다린 뒤 재결정, (c) API 유지/도입
2. **DV2 지불 의사**: "지금 로컬 구축에 투자할 최대 금액 F_max" (슬라이더). 규범 상한(저변동 0.78V, 고변동 0.31V)과 비교
3. **DV3 대기 기간**: 재결정까지 기다릴 개월 수 (0–24)

**매개/조작 점검**
- 추정 유출확률 (H2의 매개)
- 변동성 지각 점검 ("향후 1년 API 가격이 얼마나 변할 것 같은가")
- 주의 점검 문항 2개, 시나리오 이해 점검 1개

**공변량**: 직무/IT 경력, 기업 규모, 위험 선호, 수리능력(예: Berlin Numeracy), CRT, 생성형 AI 사용 경험, 프라이버시 우려(예: IUIPC 단축형). 척도 원문과 한국어 번안 타당성은 투고 전에 확인한다.

**분석 계획**
- DV1: 다항 로지스틱 회귀(요인 + 공변량). H1은 **고변동 셀에서 (a)의 비율을 0과 비교**(규범 정답이 (b)이므로)하고, 변동성 효과의 크기를 규범 효과 크기와 비교한다.
- DV2, DV3: 로그 변환 후 3원 분산분석. H1은 σ의 효과 크기가 규범 예측보다 작은지, H3은 성능 제시의 주효과로 검정한다.
- H2 매개: 사고 노출 → 추정 유출확률 → 로컬 선택(부트스트랩 간접효과).
- 상호작용은 탐색적으로 둔다(검정력 부족, 아래 참조).
- 제외 기준(사전등록): 주의 점검 실패, 응답 시간 하위 극단, 시나리오 이해 실패.

## 5. Study 2: 현상 유지/매몰비용 (H4)

- 2집단: 기존 API 계약에 지금까지 쓴 누적 비용 **낮음 / 높음** (이후 비용 구조는 동일, 규범적으로 무관)
- DV: 전환까지 기다릴 개월 수, 전환 선택 비율
- 매몰비용 크기를 3수준(낮음/중간/높음)으로 두어 용량-반응 관계를 보면 설득력이 올라간다.
- Study 1의 설계를 재사용하므로 Study 1 후속으로 진행해도 된다.

## 6. 표본 크기 (G*Power 계열 계산, α=.05, 검정력 .80)

| 검정 | 가정한 효과 | 분석 대상 N |
| --- | --- | --- |
| 1 자유도 주효과(요인 하나, 나머지 합산) | f = 0.15 | 351 |
| 같은 검정, 더 작은 효과 | f = 0.10 | 787 |
| 같은 검정, 더 큰 효과 | f = 0.20 | 199 |
| 두 집단의 선택 비율 비교 | 40% vs 55% | 346 |
| 두 집단의 선택 비율 비교 | 30% vs 45% | 324 |
| 두 집단의 선택 비율 비교 | 40% vs 50% | 776 |

- Study 1은 주효과에 f≈0.15 또는 비율 차 15%p를 목표로 **분석 대상 약 400**을 잡고, 제외율 20%를 감안해 **약 500명** 모집을 제안한다.
- 3요인 상호작용은 이 N으로는 검정력이 부족하다. 사전등록에서 주효과만 확인적 가설로 명시한다.
- 효과 크기는 가정이다. 파일럿(N≈60)으로 DV 분포와 제외율을 확인한 뒤 본 표본을 확정한다.
- 패널 비용은 현재 요금(참여 보상, 수수료)을 확인해 산정한다.

## 7. 타당도 위협과 대응

| 위협 | 대응 |
| --- | --- |
| 가상 상황이라 실제 책임이 없음 | 의사결정 품질에 연동된 보너스(규범 정답에 가까울수록 보너스) 조건을 강건성 분석으로 추가 |
| 학생·일반 패널은 의사결정자가 아님 | 직무·권한 필터 적용, 가능하면 실제 IT 관리자 소표본을 보조로 확보, 필터 통과 여부를 공변량으로 보고 |
| 규범 모형이 지나치게 정교해 보임 | 규범 벤치마크를 "참고 기준"으로만 쓰고, 결론은 조건 간 차이(H2, H3, H4)에 둔다 |
| 요구 효과(demand effect) | 변수를 피험자 간으로 배정, 목적을 숨긴 커버스토리, 매개 문항은 DV 이후에 배치 |
| 시나리오 수치의 현실성 | 정확도·비용·PII 수치를 `quant_cost` 실제 측정값으로 채우고 출처를 부록에 공개 |

## 8. 일정과 절차

1. **사전**: `quant_cost` 측정(노트북 GPU)으로 시나리오 수치 확정, 규범 벤치마크 계산 재확인
2. **IRB 승인** (소속 기관 절차에 따름), 시나리오·척도 한국어/영어 번안, 파일럿(N≈60)
3. **사전등록**(가설, 제외 기준, 분석 계획)
4. **Study 1** 본 수집 → 분석
5. 필요 시 **Study 2** 수집
6. 규범 모형과 실험 결과를 묶어 원고 작성 (학회 투고 후 ISR 확장)

## 9. 이 설계가 ISR에서 설득력을 가지려면

- 논문의 주 기여는 "관리자는 왜 그리고 어떻게 규범에서 벗어나는가"의 **메커니즘**이어야 한다. 단순히 편향 목록을 나열하면 약하다.
- 규범 모형은 간결하게 두고, 보정된 파라미터(측정값)가 연결되는 점을 강조한다.
- H2의 매개 분석과 H4의 용량-반응이 메커니즘 증거가 되므로 두 가설은 포기하지 않는 편이 낫다.

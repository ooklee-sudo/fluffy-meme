# 행동 실험 설계안 (개정): 로컬 LLM vs 클라우드 API 소싱 의사결정의 행동적 실물옵션

> 개정 내용: 전문직 패널, 분석 대상 N=90, 사전 점검 20명, 국가 중립 시나리오, 확인적 가설을 H1·H3으로 한정, **두 상태 + 명시된 보수 구조의 시나리오**(규범 정답을 응답자가 계산할 수 있게 함).
> 관련 파일: `screening_items.md` (직무·권한 확인 문항), `preregistration_draft.md`, `preregistration_aspredicted_final.md` (사전등록), `survey_instrument.md` (설문), `normative_check.py` (규범 값 검증).
> 상태: 초안. 시나리오 수치는 `quant_cost` 측정값으로 교체해야 한다. Prolific 정보는 아래 §9의 날짜 기준이며, 투고 직전에 다시 확인한다.

## 1. 목적

규범 모형(실물옵션)이 "언제 로컬 구축에 투자해야 하는가"를 예측하면, 관리자가 그 예측에서 **어디서 어떻게 벗어나는지**를 검증한다. 규범 예측의 파라미터는 `quant_cost` 측정값(q_l(b), c_l, c_a, PII 노출)으로 보정한다.

## 2. 규범 벤치마크 (두 상태 모형, 응답자가 계산 가능)

연속시간 임계식(V* = [β/(β−1)]F)은 응답자에게 할인율·드리프트를 알려 줄 수 없어 정답이 모형 가정에 의존한다. 그래서 **2기간·두 상태 모형**으로 바꾼다. 모든 금액은 오늘 달러 기준이고 이자와 물가는 무시한다(응답자에게 그렇게 안내한다).

- 구축비 F는 한 번 내면 회수할 수 없고, 지금 짓든 내년에 짓든 같다.
- 지금 지으면 올해 절감액 s도 받는다. 기다리면 s를 포기한다.
- 내년 이후 절감 가치 V는 Bad/Good 두 상태가 각 50%이고, **저변동·고변동은 평균이 같고 퍼짐만 다르다**(±10% / ±50%).
- 선택지의 기대 순가치:
  - (a) 지금 구축 = s + E[V] − F
  - (b) 12개월 대기 = E[max(V − F, 0)] (내년에 상태를 보고 지을 때만 짓는다)
  - (c) API 유지 = 0
- (a) − (b) = s − E[max(F − V, 0)]: "올해 절감액" 대 "기다려서 나쁜 상황을 피하는 가치".
- 단순 기대값 비교(E[V] − F)는 옵션을 무시하므로 두 조건 모두 (a)를 고른다. 따라서 **퍼짐에 반응해 (b)로 옮기는 것이 옵션 가치를 인식했다는 증거**다.

시나리오 수치(구축비 F 기준 s = 0.12F, 내년 평균 = 1.2F, 저변동 ±10%, 고변동 ±50%)에서:

| | (a) 지금 구축 | (b) 대기 | 최적 |
| --- | --- | --- | --- |
| 저변동 (사례 C, F=500) | 160 | 100 | **(a) 지금 구축** |
| 고변동 (사례 C, F=500) | 160 | 200 | **(b) 기다림** |

(단위: 천 달러. 사례 A, B, D도 같은 비율. 전체 표와 계산은 `normative_check.py` 및 `survey_instrument.md` §4-6.)

"그 구축비까지는 (a)가 최적인 최고 비용" F*는 저변동 1.32F, 고변동 0.84F이며, 비율 0.636, **로그 차이 −0.452**이다(모든 사례 동일).

## 3. 가설

| | 내용 | 지위 |
| --- | --- | --- |
| **H1a** | 고변동 시나리오에서 "지금 구축"(a)을 고르는 비율이 10%(규범 0%에 허용 오차 10%)를 넘는다 | **확인적** |
| **H1b** | 불확실성 증가에 따른 F_max 하락이 규범 예측(로그 차이 −0.452)보다 작다 | **확인적** |
| **H3** | 정확도만 제시할 때가 정답당 비용을 같이 제시할 때보다 "로컬 지금 구축" 선택이 적다 | **확인적** |
| **H2** | 프라이버시 사고 사례에 노출되면 로컬 선호와 추정 유출확률이 높아진다 | **탐색적** (집단당 45명, d≥0.6만 검출) |
| H4 | 매몰비용·현상 유지 | **이번 연구에서 제외** (후속) |

## 4. 설계

- **피험자 내 2×2**: 불확실성(두 상태의 퍼짐 ±10% / ±50%) × 성능 제시(정확도만 / 정확도+정답당 비용). 응답자는 시나리오 **4개**를 모두 본다. 시나리오마다 업무 사례를 다르게 하여(고객 문의 분류, 인사 기록, 계약 문서, 보험 청구) 반복 느낌과 요구 효과를 줄인다.
- **사례-조건 배정**: 라틴 방격으로 사례를 조건에 배정하고, 제시 순서를 무선화한다.
- **H2**: 응답자를 사고 사례 노출/비노출로 **무선 배정**(피험자 간)하며, 노출은 시나리오 4개 앞에 한 번 제시한다.
- **국가 중립**: 모든 금액은 USD, 특정 국가 법·규제는 언급하지 않고 "중견 규모 기업", "고객 개인정보 처리 업무"로 기술한다. 국가 필터는 두지 않는다.
- **소요 시간**: 약 17분 (시나리오 4 × 약 3분 + 선별·공변량·점검 문항).
- **선택지**: (a) 지금 구축 (b) 12개월 대기 (c) API 유지. **시범 도입(pilot) 선택지는 두지 않는다**: 학습 채널이 없는 "비가역 구축의 시점" 문제로 범위를 한정했고, 이는 한계로 명시한다(Pilot Early, Commit Late가 시범을 핵심 선택지로 모형화한다).

### 시나리오 골격 (사례마다 문안만 교체; 영어 원문은 `survey_instrument.md` §4-4)
> 귀사는 [사례] 업무에 AI를 쓰려 한다. 현재는 클라우드 API를 쓰고, 로컬 소형 모델을 자체 구축하는 선택지가 있다.
> **핵심 수치**(오늘 달러 기준): 구축비 F(회수 불가, 지금이든 내년이든 동일), 지금 구축하면 올해 절감액 s, 내년 이후 절감 가치는 Bad/Good 두 상태가 각 50%(표로 제시), 평균 표기. 저변동: 평균의 ±10%, 고변동: ±50%.
> **성능 제시**: 위 절감액에 로컬과 API의 성능 차이가 "이미 반영되어 있다"고 안내한 뒤, 정확도만 / 정확도+정답당 비용을 제시한다(규범적으로는 선택과 무관).
> **선택**: (a) 지금 구축 (b) 12개월 대기 (c) API 유지. 추가로 F_max(슬라이더 0–1.8F), 이해 점검, 불확실성 지각 점검.

### 사고 사례 (H2 노출 집단)
같은 업종 기업의 유출 사례 1문단. **제시하는 연간 유출 확률(기저율)은 두 집단에서 동일**하게 모든 응답자에게 표기한다.

## 5. 측정

- **DV1** 선택 (a/b/c), **DV2** F_max ("(b), (c)보다 (a)를 여전히 고를 최고 구축비", USD, 슬라이더 0–1.8F). DV2는 응답자에게 요구가 큰 문항이라 사전 점검에서 분포와 오류를 확인한다(문제가 크면 H1a를 주 지표로 하고 H1b는 탐색으로 내린다).
- **매개/점검**: 추정 유출확률, 불확실성 지각 점검(시나리오마다), 주의 점검 2, 시나리오 이해 점검(시나리오마다 1개, 총 4)
- **공변량**: 수리능력(짧은 척도), AI 경험, 프라이버시 우려(단축형 척도), 위험 선호. 척도 원문과 출처는 투고 전 확인.
- **직무·권한**: `screening_items.md` 참조.

## 6. 분석 요약 (상세는 `preregistration_draft.md`)

- H1a: 정확 이항 검정, H0: p ≤ 0.10 (단측).
- H1b: 응답자별 log(F_max,고) − log(F_max,저) 평균을 −0.452와 비교 (단측 일표본 t 검정, H0: 평균 ≤ −0.452).
- H3: 혼합효과 로지스틱(응답자 무선 절편)으로 "지금 구축" ~ 성능 제시 + 변동성 + 순서 + 사례.
- 다중 비교: H1a, H1b, H3에 Holm 보정.
- H2: 탐색적 보고(효과 크기와 신뢰구간 중심).

**공개 페이지에서 확인되지 않은 것 (직접 확인 필요)**
1. 직무/산업/직급/IT 전문직/의사결정권 필터가 존재하는지, 있다면 요금이 있는지
2. 그 필터가 **자기보고인지 검증값인지**. 검증값이라는 근거를 찾지 못했으므로 자기보고로 간주하고 설문 안에서 확인 문항으로 보강한다.
3. 조건을 겹쳤을 때의 **모집 가능 인원**

**연구자가 직접 해야 할 확인 절차**
1. 소속 기관 이메일로 계정을 만들고 **학술 요율**이 적용되는지 확인한다.
2. 새 연구를 만들고 **Add filters** 화면에서 직무, 산업, 직급, 고용 상태, 의사결정권 관련 필터를 찾는다.
3. 원하는 필터를 건 상태에서 **모집 가능 인원과 예상 총비용**을 화면에서 확인한다(게시 전 화면).
4. 필터가 부족하면 `screening_items.md`로 설문 안에서 선별하고, 커스텀 스크리닝의 스크린아웃 보상 규칙을 확인한다.
5. 연구 게시 전에 사전등록을 완료한다. IRB는 HY-IRB-2026-11-033으로 승인 번호가 있으므로, **승인된 프로토콜이 이 설계와 일치하는지**(전문직 패널, 가상 사고 사례와 사후 해설, 보상 금액, 해외 응답자, 데이터 보관) 확인한다.

# 행동 실험 설계안 (개정): 로컬 LLM vs 클라우드 API 소싱 의사결정의 행동적 실물옵션

> 개정 내용: 전문직 패널, 분석 대상 N=90, 사전 점검 20명, 국가 중립 시나리오, 확인적 가설을 H1·H3으로 한정.
> 관련 파일: `screening_items.md` (직무·권한 확인 문항), `preregistration_draft.md` (사전등록 초안).
> 상태: 초안. 시나리오 수치는 `quant_cost` 측정값으로 교체해야 한다. Prolific 정보는 아래 §9의 날짜 기준이며, 투고 직전에 다시 확인한다.

## 1. 목적

규범 모형(실물옵션)이 "언제 로컬 구축에 투자해야 하는가"를 예측하면, 관리자가 그 예측에서 **어디서 어떻게 벗어나는지**를 검증한다. 규범 예측의 파라미터는 `quant_cost` 측정값(q_l(b), c_l, c_a, PII 노출)으로 보정한다.

## 2. 규범 벤치마크

투자 임계 V* = [β/(β−1)]·F, β는 ½σ²β(β−1) + μβ − r = 0 의 양의 근. r = 8%, μ = 0.

| σ | β | 임계 비율 | 지금 투자해도 되는 최대 F (V/F=1.8일 때 규범) |
| --- | --- | --- | --- |
| 0.10 (저변동) | 4.53 | 1.28 | 0.78 V |
| 0.50 (고변동) | 1.44 | 3.26 | 0.31 V |

V/F = 1.8로 고정하면 저변동은 **지금 구축**, 고변동은 **기다림**이 규범 정답이다. 규범상 F_max의 고변동/저변동 비율은 0.394, 로그 차이는 −0.93이다.

## 3. 가설

| | 내용 | 지위 |
| --- | --- | --- |
| **H1a** | 고변동 시나리오에서 "지금 구축"을 고르는 비율이 10%(규범 0%에 허용 오차 10%)를 넘는다 | **확인적** |
| **H1b** | 변동성 증가에 따른 F_max 하락이 규범 예측(로그 차이 −0.93)보다 작다 | **확인적** |
| **H3** | 정확도만 제시할 때가 정답당 비용을 같이 제시할 때보다 "로컬 지금 구축" 선택이 적다 | **확인적** |
| **H2** | 프라이버시 사고 사례에 노출되면 로컬 선호와 추정 유출확률이 높아진다 | **탐색적** (집단당 45명, d≥0.6만 검출) |
| H4 | 매몰비용·현상 유지 | **이번 연구에서 제외** (후속) |

## 4. 설계

- **피험자 내 2×2**: 변동성(저/고) × 성능 제시(정확도만 / 정확도+정답당 비용). 응답자는 시나리오 **4개**를 모두 본다. 시나리오마다 업무 사례를 다르게 하여(고객 문의 분류, 인사 기록, 계약 문서, 보험 청구) 반복 느낌과 요구 효과를 줄인다.
- **사례-조건 배정**: 라틴 방격으로 사례를 조건에 배정하고, 제시 순서를 무선화한다.
- **H2**: 응답자를 사고 사례 노출/비노출로 **무선 배정**(피험자 간)하며, 노출은 시나리오 4개 앞에 한 번 제시한다.
- **국가 중립**: 모든 금액은 USD, 특정 국가 법·규제는 언급하지 않고 "중견 규모 기업", "고객 개인정보 처리 업무"로 기술한다. 국가 필터는 두지 않는다.
- **소요 시간**: 약 15분 (시나리오 4 × 약 2.5분 + 선별·공변량·점검 문항).

### 시나리오 골격 (사례마다 문안만 교체)
> 귀사는 [사례] 업무에 LLM을 쓰고자 한다. 현재는 클라우드 API를 쓴다. 로컬 소형 모델을 자체 구축하는 선택지가 있다. 로컬 구축의 일회성 비용은 F, 로컬 구축으로 얻는 향후 3년 절감 가치의 현재가치는 V = 1.8F이다.
> [변동성 문구] 저: "API 가격과 소형 모델의 성능은 향후 1년간 거의 변하지 않을 전망이다." / 고: "API 가격과 소형 모델의 성능은 향후 1년간 크게 오르내릴 수 있다. 같은 예측기관들의 전망치도 크게 갈린다."
> [성능 제시] 정확도만: "로컬 모델 정확도 X%, API 정확도 Y%." / 병기: 위에 "정확한 답 하나당 비용: 로컬 $a, API $b"를 추가.
> 선택: (a) 지금 로컬 구축 (b) 12개월 기다린 뒤 재결정 (c) API 유지. 추가로 F_max(슬라이더), 대기 개월 수.

### 사고 사례 (H2 노출 집단)
같은 업종 기업의 유출 사례 1문단. **제시하는 연간 유출 확률(기저율)은 두 집단에서 동일**하게 모든 응답자에게 표기한다.

## 5. 측정

- **DV1** 선택 (a/b/c), **DV2** F_max (USD, 슬라이더 0–1.2V), **DV3** 대기 개월 수 (0–24)
- **매개/점검**: 추정 유출확률, 변동성 지각 점검, 주의 점검 2, 시나리오 이해 점검 2
- **공변량**: 수리능력(짧은 척도), AI 경험, 프라이버시 우려(단축형 척도), 위험 선호. 척도 원문과 출처는 투고 전 확인.
- **직무·권한**: `screening_items.md` 참조.

## 6. 분석 요약 (상세는 `preregistration_draft.md`)

- H1a: 정확 이항 검정, H0: p ≤ 0.10 (단측).
- H1b: 응답자별 log(F_max,고) − log(F_max,저) 평균을 −0.93과 비교 (단측 일표본 t 검정).
- H3: 혼합효과 로지스틱(응답자 무선 절편)으로 "지금 구축" ~ 성능 제시 + 변동성 + 순서 + 사례.
- 다중 비교: H1a, H1b, H3에 Holm 보정.
- H2: 탐색적 보고(효과 크기와 신뢰구간 중심).

## 7. 표본과 단계

| 단계 | 인원 | 목적 |
| --- | --- | --- |
| **사전 점검** | 전문직 20명 | 필터·선별 통과율, 소요 시간, 점검 문항 실패율, 모집 속도, 효과 크기의 대략치. **가설 검정 안 함**, 본 표본에 포함하지 않음 |
| **본 수집** | 분석 대상 90 (모집 약 113, 상한 140) | H1a, H1b, H3 확인적 검정 |

- H1b와 H3은 피험자 내라서 dz≈0.3에서 N=90으로 검정력 약 0.80이다(대응 비교 기준).
- 사전 점검의 진행 기준(사전등록): ① 선별 통과자 모집 속도가 허용 범위, ② 중앙 소요 시간 ≤ 17분, ③ 주의 점검 실패율 ≤ 25%, ④ 설문 오류 없음. 효과 크기는 n=20이라 매우 불확실하므로 **단독 기준으로 쓰지 않고** 참고만 한다.

## 8. 예산 (§9의 Prolific 확인 값 기준)

가정: 보상은 시급 환산 $20, 15분이므로 응답자당 $5.00. 필터와 선별 비용은 §9 참조.

| 항목 | 인원 | 수수료 33.3% (학술) | 수수료 42.857% (기업) |
| --- | --- | --- | --- |
| 사전 점검 | 20 | 약 $133 | 약 $143 |
| 본 수집 | 113 | 약 $753 | 약 $807 |
| 선별 탈락 보상(가정 최대 150명 × $0.14) | - | 약 $28 | 약 $30 |
| **합계** | | **약 $914 (약 130만 원, 1,400원/$ 가정)** | **약 $980** |

- 본 수집이 140명 상한까지 가면 약 $190~$200 추가.
- 플랫폼 수수료의 부가세는 위치에 따라 붙을 수 있다.
- 보상은 시급 환산 $12(권장 최소) 이상이어야 하며, 보너스는 최소 시급 충족용으로 쓸 수 없다.

## 9. Prolific 확인 사항 (조사일 기준 공개 페이지)

출처는 Prolific 도움말 센터(researcher-help.prolific.com)이며, 문서 날짜가 있는 것은 날짜를 적었다.

| 항목 | 확인된 내용 | 출처 날짜 |
| --- | --- | --- |
| 수수료 | 참여자 보상의 **42.857%(기업)**, **33.3%(학술·비영리)**. 학술 요율은 소속 기관 이메일과 학술/비영리 선택이 필요하며, Gmail 등 개인 도메인은 불가 | 2026-10-09 |
| 시급 | 권장 최소 **$12/시간**, 절대 최소 **$8/시간**. 보너스에도 같은 수수료 | 2026-10-09 |
| 기본 프리스크리너 | 기존 프리스크리너 사용은 **추가 비용 없음** | 2026-10-09 |
| 커스텀 스크리닝 | 인원당 추가 요금이 아니라 **스크린아웃 보상을 연구마다 설정**(최소 $0.14), 연구 시작 시 선결제, 미사용분 환불 | 2026-06-12 |
| 필터 | AND/OR 논리 지원, "현재 직무(Current job role)", 언어, 거주국, 연령, 학력 필터가 있음 | 2026-07-13 |

**공개 페이지에서 확인되지 않은 것 (직접 확인 필요)**
1. 직무/산업/직급/IT 전문직/의사결정권 필터가 존재하는지, 있다면 요금이 있는지
2. 그 필터가 **자기보고인지 검증값인지**. 검증값이라는 근거를 찾지 못했으므로 자기보고로 간주하고 설문 안에서 확인 문항으로 보강한다.
3. 조건을 겹쳤을 때의 **모집 가능 인원**

**연구자가 직접 해야 할 확인 절차**
1. 소속 기관 이메일로 계정을 만들고 **학술 요율**이 적용되는지 확인한다.
2. 새 연구를 만들고 **Add filters** 화면에서 직무, 산업, 직급, 고용 상태, 의사결정권 관련 필터를 찾는다.
3. 원하는 필터를 건 상태에서 **모집 가능 인원과 예상 총비용**을 화면에서 확인한다(게시 전 화면).
4. 필터가 부족하면 `screening_items.md`로 설문 안에서 선별하고, 커스텀 스크리닝의 스크린아웃 보상 규칙을 확인한다.
5. 연구 게시 전에 사전등록을 완료하고 IRB 상태를 확인한다.

## 10. 타당도 위협과 대응

| 위협 | 대응 |
| --- | --- |
| 자기보고 직무·권한 | 설문 내 확인 문항, 응답 일관성 검사, 사전등록한 자격 규칙 |
| 모집 풀 부족 | 사전 점검에서 속도 확인, 상한 140명, 필터를 단계적으로 완화(사전등록에 사유 기록) |
| 요구 효과 | 사례·문안 교체, 순서 상쇄, 목적을 숨긴 커버스토리, 매개 문항은 선택 이후 |
| 효과가 규범보다 작음 | H1a, H1b의 단측 검정과 효과 크기·신뢰구간 모두 보고 |
| 가상 상황 | 보너스 연동 강건성 조건은 예산 여유 시 후속 |
| 국가 중립이라 현지 규제 맥락이 없음 | 한계로 명시하고, 후속 연구에서 국내 패널로 반복 |

## 11. 일정

1. `quant_cost` 측정(노트북 GPU)으로 시나리오 수치 확정
2. IRB 확인, §9의 Prolific 확인, 시나리오·문항 검수
3. 사전 점검 20명 → 진행 기준 판정
4. **사전등록 제출** (본 수집 전, 점검 결과 반영 후)
5. 본 수집 → 분석

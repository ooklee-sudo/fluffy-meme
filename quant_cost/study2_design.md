# Study 2 설계안: 프라이버시 사고 사례와 성능 제시가 AI 소싱 결정을 왜곡하는가

> 이론은 `theory_h2_h3.md`, 설문은 `study2_survey_instrument.md`, 사전등록은 `study2_preregistration_aspredicted.md`, 규범 값 검증은 `normative_check_study2.py`.
> Study 1(옵션 가치, H1)의 설문·사전등록은 보류 상태로 남겨 둔다(`survey_instrument.md`, `preregistration_aspredicted_final.md`). 선별 문항(`screening_items.md`), Prolific 확인 사항(`experiment_design.md` §9), IRB 번호는 그대로 쓴다.
> **확정된 것이 아니라 제가 정한 기본값**: λ=2%/6%, L=200만 달러, 비용 수치. 지도교수와 검토한 뒤 사전 점검 전에 고정한다.

## 1. 핵심 아이디어

관리자가 로컬 모델과 클라우드 API 중 하나를 고르는 **1년짜리 결정**에서, 규범적으로는 선택이 같아야 하는 두 가지 조작이 결정을 움직이는지 본다.
- **H2**: 프라이버시 사고 사례(가상)를 읽었는가 → 노출 확률 λ에 대한 지불 의사와 민감도가 달라지는가
- **H3**: 성능을 정확도만 보여주는가, 정확도 + 정답당 비용으로 보여주는가 → 선택이 달라지는가

## 2. 규범 기준선 (응답자가 계산 가능, 위험중립 가정)

비용은 모두 연간, 단위는 천 달러.
- 로컬은 운영비를 **B** 절감하지만 정확도가 낮아 오류 비용이 **E** 더 든다. 순 운영 이점 = B − E.
- API는 연 **λ**의 확률로 데이터가 노출되고, 노출 시 손실 **L**이 든다. 기대 프라이버시 손실 = λL.
- **로컬의 순 이점 = (B − E) + λL**. 0보다 크면 로컬이 최적이다.
- 규범적 지불 의사(API의 노출 위험을 없애는 값) = λL.

기본값(사례 C): B = 100, E = 180, L = 2,000.

| λ | 순 이점(로컬) | 규범 선택 | 규범 WTP = λL |
| --- | --- | --- | --- |
| 2% (낮음) | −40 | **API** | 40 |
| 6% (높음) | +40 | **로컬** | 120 |

손익분기 λ* = (E − B)/L = 4%. 사례별 크기만 다르고 비율은 같다(전체는 `normative_check_study2.py`). 규범적으로 **ln(WTP 높음/낮음) = ln 3 = 1.099**이다.

규범 선택은 λ에 따라 **뒤집힌다**. 따라서 "λ에 대한 민감도"가 규범적으로 의미를 갖고, 사고 사례가 이 민감도를 낮추는지(H2c)를 깨끗하게 볼 수 있다. 사고 사례와 성능 제시 형식은 규범 값을 바꾸지 않는다(H2: 사고 사례는 기저율과 무관, H3: 성능 정보는 절감·오류 비용에 이미 반영).

## 3. 설계

혼합 설계. 피험자 간 1개, 피험자 내 2개.
- **피험자 간(H2)**: 사고 사례 노출 / 비노출(무선 50:50). 시나리오 앞에서 한 번 읽는다.
- **피험자 내(H2c, H3)**: 노출 확률 λ(낮음 2% / 높음 6%) × 성능 제시(정확도만 / 정확도 + 정답당 비용) = 4개 시나리오. 업무 사례 4종(A–D)을 라틴 방격으로 셀에 배정하고, 제시 순서는 무선화한다.
- 국가 중립, USD, 기업 규모와 업무 맥락은 Study 1과 같다.

## 4. 가설과 분석 (사전등록과 일치)

**주(primary) 검정, α = .05**
- **H2c** 사고 사례에 노출된 집단은 λ에 대한 민감도가 낮다. 응답자별 S = 평균 ln(WTP/L)(높은 λ) − 평균 ln(WTP/L)(낮은 λ)가 노출 집단에서 더 작다(규범 값 ln 3 = 1.099). WTP를 손실 L로 나누어 사례 크기 차이를 없애고, WTP=0은 0.001 L로 대체한다. Welch t 검정, 양측.

**확인적 이차 검정, Holm 보정(α = .025 기준)**
- **H2a** 사고 사례 노출 집단의 평균 ln(WTP/L)이 더 높다.
- **H3a** 정확도만 제시할 때 "로컬 선택" 확률이 정확도 + 정답당 비용 제시일 때보다 낮다(혼합효과 로지스틱, 양측).

**계획된 보조 분석(확인적 지위 아님)**
- **H2b** 사고 사례 → 추정 노출 확률의 초과분(λ̂ − 제시된 λ) → ln(WTP/L) 매개(부트스트랩)
- **H3b** 성능 제시 → 지각된 품질 격차 → 로컬 선택 매개
- 조작 점검: 높은 λ에서 로컬 선택이 더 많은가

**탐색적**: H3c(수리능력·AI 경험·권한의 조절), H4(사고 사례 × 성능 제시 상호작용), 가용성 이론(λ̂ 수준 이동)과 확률 둔감 이론(기울기 감소)의 상대적 지지.

## 5. 표본과 예산

가정: α, 검정력 .80, 제외율 20%.
| 검정 | 가정한 효과 | 필요 분석 대상 N |
| --- | --- | --- |
| H2c (집단 간, α=.05) | d = 0.35 | 260 |
| H2a (집단 간, α=.025) | d = 0.40 | 242 |
| H3a (피험자 내, α=.025) | dz = 0.25 | 155 |

**목표: 분석 대상 260명(모집 약 325, 상한 400).** 효과 크기는 가정이므로 사전 점검 20명의 결과로 확인한다(단 n=20이라 매우 불확실하다). H2c는 Holm 가족 밖이라 α=.05로 계획했다. Holm 가족(H2a, H3a)은 α=.025 수준에서 검정력을 확보했다.

예산(소요 약 18분, 시급 환산 $20, 보상 $6.00; Prolific 학술 수수료 33.3% / 기업 42.857%):
| 항목 | 학술 | 기업 |
| --- | --- | --- |
| 사전 점검 20명 | 약 $160 | 약 $171 |
| 본 수집 325명 | 약 $2,600 | 약 $2,786 |
| 선별 탈락 보상(150 × $0.14) | 약 $28 | 약 $30 |
| **합계** | **약 $2,790 (약 390만 원, 1,400원/$ 가정)** | **약 $2,990** |

상한 400명까지 가면 학술 기준 약 $600 추가. 효과가 더 작으면(d=0.30) 분석 대상이 약 350명 필요해 예산이 늘어난다.

## 6. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 사고 사례가 합리적으로 정보를 준다고 해석(기저율이 사실은 더 높다) | 모든 시나리오에서 λ를 "업계 전체의 보고된 사고를 모두 반영한 위험팀 추정치"로 제시한다. 그래도 λ̂가 오르는지가 H2b의 핵심이다. |
| 명시적으로 무시하라는 지시가 효과를 지움 | 사고 사례를 무시하라는 문구는 넣지 않는다. 위의 정보 제시만 한다. |
| WTP 질문이 어려움 | 슬라이더에 숫자 표시, 사전 점검에서 분포와 이해 오류 확인. 문제가 크면 DV1(선택)을 주 지표로 바꾸는 규칙을 사전등록에 둔다. |
| 곱셈(λ×L)이 어려워 민감도가 줄어듦 | 곱을 일부러 보여주지 않는다(확률 둔감 검정의 핵심). 수리능력을 공변량·조절변수로 쓴다. |
| 요구 효과 | 사고 사례는 피험자 간 배정, 목적을 숨긴 커버스토리, 매개 문항은 선택·WTP 뒤에 배치 |
| 한 개의 연구 | 후속으로 일반 패널 반복, 다른 업무 맥락, 필요하면 실제 기업 인터뷰를 추가(`theory_h2_h3.md` §7) |
| IRB 승인 범위 | Study 2는 시나리오와 소요 시간이 달라 **변경 심의나 별도 승인이 필요한지** IRB 사무국에 확인한다(HY-IRB-2026-11-033). |

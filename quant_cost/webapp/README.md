# Study 2 웹 설문 (직접 구현판)

Qualtrics 없이 쓰는 설문입니다. 문안, 수치, 라틴 방격, 무선 배정은 `../study2_survey_english.md`와 `../study2_survey_instrument.md`를 그대로 구현했습니다. 의존성은 **Python 표준 라이브러리뿐**입니다(서버). 설문 화면은 순수 JavaScript라 빌드 과정이 없습니다.

| 파일 | 역할 |
| --- | --- |
| `public/index.html`, `style.css` | 화면 틀, 스타일(밝은·어두운 모드, 휴대폰 대응) |
| `public/content.js` | **응답자에게 보이는 모든 문안과 설계 수치**(사례 A~D, 셀 C1~C4, 라틴 방격). 문구나 숫자를 바꾸려면 여기만 고친다 |
| `public/app.js` | 흐름, 검증, 저장, 무선화 |
| `public/config.js` | Prolific 완료 URL 등 배포 설정 |
| `server.py` | 정적 파일, 균형 배정 `/api/assign`, 저장 `/api/save`. IP 주소를 기록하지 않음 |
| `export_csv.py` | 저장된 응답을 분석용 한 줄짜리 CSV로 변환(사전등록 변수와 제외 플래그 포함) |
| `test_e2e.js` | 브라우저 자동 테스트(32개 검사) |

## 실행 (이 컴퓨터에서 시험)

```bash
cd ~/llm-sourcing
git pull
python3 quant_cost/webapp/server.py --port 8765
```
브라우저에서 `http://127.0.0.1:8765/`를 엽니다. Prolific 변수를 흉내 내려면 `http://127.0.0.1:8765/?PROLIFIC_PID=TEST01&STUDY_ID=S1&SESSION_ID=X1`처럼 엽니다. 응답은 `quant_cost/webapp/data/participants/`에 JSON으로 저장됩니다. 서버를 끄려면 `Ctrl+C`.

자동 테스트(Node와 Playwright가 있을 때): `node quant_cost/webapp/test_e2e.js`

## 설문이 하는 일 (사전등록과의 대응)
- 동의, 자격 문항(S1~S8), 부적격이면 종료. **S8(정책)은 자격 기준이 아니다**(전면 금지 응답자도 계속).
- 서버가 **8개 그룹(뉴스 2 × 라틴 방격 버전 4)을 가장 적게 찬 곳 순으로 균형 배정**하고 시나리오 제시 순서를 무선화한다(같은 참가자가 새로고침해도 같은 배정).
- 시나리오마다 한 화면에 본문 + Q1(이해 점검), Q2(선택), Q3(지불 의사, 숫자 입력). **다음 화면에서 Q4(추정 확률), Q5(품질 격차)**를 묻는다(선택과 지불 의사 뒤에 측정, 사전등록 순서).
- 시나리오 뒤: 주의 점검 A1, 공변량(수리능력, AI 경험, 개인정보 우려, 위험 선호, 주의 점검 A2, 재량, 요소 순위, 산업, 지식재산, 기밀 정보), 일관성 확인(C1), 인구통계, 해설.
- 제외는 설문 안에서 하지 않고 `export_csv.py`가 **플래그만** 만든다(`excluded` 열). 분석에서 걸러 낸다.

## 설정 (`public/config.js`)
- `completeUrl`: Prolific 연구 설정에서 복사한 **완료 URL**. 비워 두면 시험 모드(완료 링크 없음).
- `screenoutUrl`: 부적격자를 보낼 곳(Prolific 화면에서 정한 절차). 비워도 됨.

Prolific 연구를 만들 때 설문 주소는 아래 형태로 입력합니다(주소의 `PROLIFIC_PID` 등은 Prolific이 채워 줌. 현재 Prolific 안내 화면의 표기와 같은지 확인하세요).
```
https://<설문을 올린 주소>/?PROLIFIC_PID={{%PROLIFIC_PID%}}&STUDY_ID={{%STUDY_ID%}}&SESSION_ID={{%SESSION_ID%}}
```

## 데이터를 어디에 저장하고 어떻게 올리나 (결정할 것)
참가자가 Prolific을 통해 접속하므로 설문은 **인터넷에서 HTTPS로 접속 가능한 곳**에 있어야 합니다. 이 서버는 응답을 **서버가 있는 컴퓨터의 `data/` 폴더**에 저장합니다. 선택지는 다음과 같습니다.

| 방식 | 데이터 위치 | 장단점 |
| --- | --- | --- |
| **A. 학교 서버/클라우드**(연구지원팀 문의) | 학교 관리 | IRB·개인정보 규정에 가장 안전. 설치와 운영을 학교에 요청해야 함 |
| **B. 국내 리전 VPS** 등 직접 임대 | 한국 내 서버 | 위치와 접근을 직접 통제. HTTPS 설정, 백업, 보안 업데이트를 직접 관리 |
| **C. 노트북 + 터널** (사전 점검용) | **노트북** | 설치가 빠름. 노트북이 켜져 있어야 하고, 분실·고장 위험. 소규모 사전 점검(10명)에 적합 |
| 외부 서비스(Firebase 등) | 해외 사업자 서버 | 쉬움. **국외 이전·약관을 IRB 계획과 대조해야 함** |

**어느 쪽이든 지킬 것**
- IRB 계획서에 적은 **저장 위치, 보관 기간, 접근 권한**을 따른다.
- 수집하는 정보: Prolific ID(가명), 응답, 시각, 선택적 국가. **IP 주소와 브라우저 종류는 저장하지 않는다**(코드 확인). 자유 서술 없음.
- 분석용 파일에서는 Prolific ID를 지우고 별도로 보관한다(보상 지급과 연결할 때만 사용).
- 데이터 폴더는 **저장소에 올리지 않는다**(`.gitignore`에 포함).
- **백업**(암호화 폴더)을 다른 곳에 둔다.

### 방식 C 사전 점검 예시 (제가 시험하지 못한 부분)
서버를 켠 노트북을 외부에 공개하려면 터널 서비스(예: Cloudflare Tunnel, ngrok)가 필요합니다. 사용법은 각 서비스의 현재 안내를 따르세요. 터널 주소가 설문 주소가 됩니다. **사전 점검이 끝나면 터널을 닫고 서버를 끕니다.**

## 한계
- **실제 참가자로는 시험하지 못했다.** 자동 테스트는 브라우저로 모든 화면을 통과시키는 방식이고, 휴대폰 크기 화면도 확인했다(실기기 아님).
- 서버는 간단한 구현이다(단일 프로세스, 로그인·속도 제한 없음). 공개 인터넷에는 **역방향 프록시(HTTPS)** 뒤에 두는 것이 좋다.
- 배정 횟수는 **배정 시점**에 세어서, 중도 이탈자가 있으면 완료 기준으로는 완전히 균등하지 않다.
- Qualtrics와 달리 자동 분석 도구가 없다. `export_csv.py`가 사전등록 변수를 만든다.

# ISR 투고를 위한 설계과학(DSR) 재구성 계획

작성일: 2026-10-09. 대상: Text-Hawkes (텍스트 조건부 Hawkes 과정).
이 문서는 **계획과 설계**입니다. 아직 수행되지 않은 실험의 결과는 어디에도 쓰지 않았습니다.

## 0. 솔직한 전제

- ISR은 방법론 논문이 아니라 **IS 지식 기여**를 보는 저널입니다. 지금 원고(`main.tex`)는 알고리즘 벤치마크 중심이라 그대로는 맞지 않습니다.
- 설계과학 논문으로 가려면 (1) 실제 비즈니스 문제, (2) 인공물(artifact), (3) 엄밀한 평가, (4) 설계 지식(원칙/이론)이 모두 필요합니다.
- 이 계획을 모두 수행해도 채택은 보장되지 않습니다. 최상위 저널이라 심사자 평가에 달려 있고, 특히 **IS 분야의 이론적 연결**은 제가 대신 만들 수 없는 부분입니다(해당 분야 문헌에 정통한 공저자 또는 자문이 필요합니다).
- 현재 증거에는 약점이 있습니다: 합성 실험에서 이점은 소량 데이터에 한정되었고, 실데이터 실험은 진행 중이며, Amazon에서 동시 사건(timestamp tie)에 의한 우도 부풀림을 발견해 β 상한으로 처리했습니다(상한에 붙는 현상은 남음).

## 1. 문제 정의 (Problem relevance)

**비즈니스 문제**: 새 서비스·상품군·기능을 시작한 조직은 고객 행동 이벤트 로그가 **적은 상태**에서 "다음에 어떤 행동이 언제 일어나는가"와 "어떤 행동이 어떤 행동을 유발하는가"를 알아야 합니다(프로모션 시점, 인력·재고 계획, 추천). 그런데 이벤트 유형(상품 카테고리, 문의 유형, 장애 라벨)은 **이미 의미 있는 이름**을 갖고 있습니다.

**기존 인공물의 한계** (문헌 조사 `semantic_hawkes/LITERATURE.md` 참조)
- 고전 Hawkes: 해석 가능하나 K×K 파라미터라 데이터가 적으면 불안정
- 신경망 TPP(NHP, THP): 유연하나 데이터가 많이 필요하고 의존 구조가 불투명
- LLM 기반 TPP(TPP-LLM 등): 의미를 쓰지만 계산 비용이 크고 해석 가능한 상호작용 구조가 없음

**인공물**: Text-Hawkes. 이벤트 유형 텍스트의 (고정된) LLM 임베딩에서 Hawkes 파라미터를 생성.

## 2. 요구사항 3: 실제 조직 데이터 평가와 비즈니스 지표

### 2.1 무엇이 필요하고, 누가 해야 하나

| 항목 | 상태 | 담당 |
|---|---|---|
| **실제 조직의 이벤트 로그** (고객 구매/문의/장애 등 + 유형 이름) | **없음. 제가 만들 수 없음** | **연구자 (데이터 확보·IRB/계약·익명화)** |
| 공개 데이터 기반 시나리오 평가 (Amazon, Stack Overflow, NYC Taxi) | 진행 중 | 코드로 수행 |
| 비즈니스 지표 정의와 계산 | 아래 정의, 구현 일부 | 코드로 수행 |
| 도메인 전문가 해석 평가 | 미수행 | 연구자 (전문가 모집) |

조직 데이터를 구하는 현실적 경로: 기업·기관과의 공동연구 협약, 소속 대학·병원·지자체 운영 로그, 산학과제 데이터. **ISR은 naturalistic evaluation(실제 환경 평가)을 높게 평가하므로 이것이 가장 큰 격차입니다.**

### 2.2 평가 시나리오와 지표 (공개 데이터로 먼저 수행)

| 시나리오 | 데이터 | 비즈니스 의미 |
|---|---|---|
| 상품 카테고리 간 구매 연쇄 | Amazon Review (K=18) | 교차 판매·다음 구매 카테고리 예측 |
| 커뮤니티 참여 배지 | Stack Overflow (K=25) | 사용자 참여 유지·보상 설계 |
| 이동 수요 | NYC Taxi (K=8) | 지역별 수요 예측 |

**지표** (모두 실제 데이터에서 계산되며, 금전적 가치로의 환산은 *시나리오 가정*이지 실측이 아님)
1. **데이터 효율**: 학습 곡선(학습 시퀀스 수 50/100/200/500/전체)에서 *전체 데이터 NHP의 우도(또는 정확도)에 도달하는 데 필요한 최소 시퀀스 수*. 신규 서비스에서의 관측 기간(=데이터 수집 비용)으로 환산 가능.
2. **다음 이벤트 유형 정확도**(현재 구현), **시간 오차 RMSE**(현재 구현), **테스트 로그우도**(현재 구현).
3. **계산 비용**: 학습 시간, 추론 시간, 모델 파라미터 수, LLM 호출 여부(Text-Hawkes는 임베딩을 한 번만 계산). *아직 측정 코드 없음 → 추가 필요.*
4. **해석성**: 학습된 분기비 행렬 A의 상위 관계를 도메인 전문가가 평가(그럴듯함/의미 없음/잘못됨). *전문가 평가 필요.*
5. (선택) top-k 정확도: EasyTPP 기본 평가에 없어 추가 구현 필요.

### 2.3 통제 실험 (이 설계에서 가장 중요)

"텍스트가 의미를 전달해서 좋아지는 것인지, 단지 파라미터 수가 줄어서 좋아지는 것인지"를 가르는 대조군을 구현했습니다.

| 변형 (`--emb_tags`) | 의미 | 예상 해석 |
|---|---|---|
| `qwen` | 올바른 LLM 임베딩 | 제안 방법 |
| `hash` | 어휘 겹침만 반영 | LLM이 어휘 겹침 이상을 주는가 |
| `qwenperm` | 같은 임베딩을 **잘못된 유형에 배정** | 이점이 사라져야 의미 효과임 |
| `random` | 정보 없는 임베딩 | 구조적 정규화 효과만 남음 |
| Free Hawkes | 텍스트 없음 | 기준선 |

`qwen`이 `qwenperm`/`random`보다 낫지 않다면, "텍스트 의미를 활용한다"는 주장은 **기각**됩니다. 이 경우 논문의 주장을 바꿔야 합니다.

실행 예 (현재 1단계 실험이 끝난 뒤 권장, CPU 경합 방지):
```
python -m semantic_hawkes.bench --epochs 8 --sizes 200 0 --seeds 2019 --models SemHawkesTPP --emb_tags hash qwenperm random
```

## 3. 요구사항 4: 설계 원칙 (Design principles)

Gregor & Hevner (2013)의 지식 기여 틀에서, 새 문제 영역에 대한 *개선(improvement)* 기여로 설계 원칙을 도출합니다. 아래는 **가설 형태의 설계 원칙**이며, 각각 검증 실험과 기각 조건을 붙였습니다. 검증되지 않은 원칙은 논문에서 원칙으로 주장하면 안 됩니다.

| 원칙 | 내용 | 근거(현재) | 검증 실험 | 기각 조건 |
|---|---|---|---|---|
| **DP1 의미 사전지식** | 이벤트 유형의 텍스트 의미를 임베딩으로 주입해, 의미가 유사한 유형이 유사한 상호작용 구조를 공유하게 하라 | 합성 실험: 20~200 시퀀스에서만 우도 이득 | 통제 실험 2.3 + 학습 곡선 | `qwen`이 `qwenperm`/`random`을 넘지 못함 |
| **DP2 구조 보존** | 해석성과 정확한 우도를 위해, 신경망 강도 대신 비음수 분기비를 가진 파라메트릭 Hawkes 구조를 유지하라 | 설계상의 성질(닫힌 형태 우도) | 해석 평가(전문가), 우도 정확성 테스트 | 전문가가 학습된 A를 의미 없다고 판단 |
| **DP3 해상도 제약** | 시간 해상도(동일 시각 사건)를 고려해 감쇠율 상한을 두어라 | **우리가 발견한 실패**: 상한 없이 Amazon에서 β≈5,000 | 상한 값 민감도 분석 (β_max ∈ {5, 20, 100}) | 상한이 결과를 좌우하면 원칙이 아니라 튜닝 |
| **DP4 인코더 분리** | LLM은 고정된 텍스트 인코더로만 쓰고 유형당 한 번만 호출하라 | 설계상의 성질(비용) | 계산 비용 측정 2.2-3 | 비용 이점이 없거나, 미세조정 모델이 크게 우수 |
| **경계 조건** | DP1의 이득은 (i) 학습 데이터가 적고 (ii) 유형 이름이 정보적일 때 | 합성: 800 시퀀스에서 역전 | 학습 곡선 + 유형 이름 정보량 조작 | 이득이 데이터 크기·이름 정보량과 무관 |

## 4. 이론적 연결 (연구자가 채워야 함)

ISR 심사는 "IS 문헌에 무엇을 더하는가"를 묻습니다. 후보 연결 고리:
- **콜드스타트 문제**와 추천시스템 문헌 (IS에서 오래 다뤄진 주제)
- **설명 가능한 AI**와 의사결정 지원 (해석 가능한 상호작용 구조)
- **지식 재사용/전이**: 사전 지식이 데이터를 대체하는 조건
- 설계과학 방법론: Hevner et al. (2004), Peffers et al. (2007), Gregor & Hevner (2013)

이 연결은 해당 문헌을 직접 검토하는 공저자나 자문이 필요합니다. 제가 검증되지 않은 인용으로 채우면 안 됩니다.

## 5. 수행 순서와 시간

1. (진행 중) 1단계: β 상한 적용 Hawkes, 시드 2019 — 약 2~3시간
2. 통제 실험(`hash`, `qwenperm`, `random`) — 약 3~5시간 (소량 설정 중심)
3. 학습 곡선(50/100/200/500/전체) — 수 시간 추가 (CPU 한계로 일부 데이터셋만 권장)
4. 추가 시드(2020, 2021) — 수 시간
5. 계산 비용 측정 코드 추가
6. **조직 데이터 확보 및 평가 — 연구자 몫, 수 주~수 개월**
7. 전문가 해석 평가 — 연구자 몫
8. 원고를 DSR 구조(문제-인공물-평가-설계 원칙-이론)로 재작성

## 6. 위험

- 통제 실험에서 텍스트 효과가 입증되지 않으면 핵심 기여가 무너집니다.
- 조직 데이터 확보가 지연되면 ISR 투고 시점이 늦어집니다.
- 테뉴어 심사에서 ISR 한 곳에 의존하는 것은 위험합니다. 병행 투고 후보(Decision Support Systems, Information & Management, ESWA 등)를 확보하는 것을 권합니다.
